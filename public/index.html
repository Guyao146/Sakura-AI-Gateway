上游站点

OpenAI 兼容协议适用于 sub2api / newapi 常见接口；Anthropic 协议会使用 /v1/messages。可测试连接、查询余额，并查看上游熔断状态。余额查询不会影响熔断状态。

模型路由

精确匹配优先；也可以把本地模型名写为 * 作为兜底路由。只有一个上游时可不配路由。

本地模型选择

相同模型 ID（忽略大小写）会合并成一项，并按 ID 前缀分组；显示名称沿用「当前名称」，转发时按各中转站自己的拼写发送。每个模型可选择“自动选择”全部同名来源站，也可在下拉框中固定某一个站；自动模式会轮询健康站点，并在连接失败、429、5xx 或熔断时切换。可以设置本地别名、默认思考强度和接口协议（自动 / Responses / Chat Completions）。上游没有给出思考档位时，可点「拉取思考强度」发送极小探测请求确认真实档位，会消耗少量额度。

每行「拉取能力」刷新输入/输出模态与思考档位；未声明档位时会发送少量付费探测请求。模态未声明则保持未知，不按模型名推断。每个模型可单独指定转译模型：只将明确不支持的附件转成文字，留空则报错。转译会把附件发送给另一个模型，增加费用与延迟，且可能损失细节；调用 Key 必须同时获准访问两个模型。不支持输出模态转译。

本地调用 Key

本地 APP 调用时使用这里的 Key。新建或编辑时可设置允许的分组，并逐个勾选组内模型；未授权模型不会展示且调用返回 403。旧 Key 默认不限制。完整 Key 可直接查看和复制；请求头可用 Authorization: Bearer ... 或 x-api-key: ...。

管理认证

远程访问管理后台时使用下面选择的方式；两种方式可以随时切换。模型调用接口不受影响，仍使用本地 API Key。

远程管理认证方式

管理员账号

密码使用 scrypt 哈希后保存在本地配置中，明文不会回传到前端，也不会写入请求日志。账号在 password 模式下至少保留一个启用状态。

可靠性设置

控制上游请求等待时间和故障转移行为。每个上游失败后先原地重试（同一上游重试次数），重试次数用尽再切换到下一优先级的备用上游；最大备用尝试次数为 0 时表示不限制，设置修改立即保存。
